# Bounded FeatureScript cuboid port

This standalone Python 3.8+ utility manually maps the exact authored token
template in `bounded-cuboid.fs` to a declarative native package. It uses only the
standard library. It does not execute FeatureScript.

From the repository root, export to an existing directory:

```sh
python -B tools/featurescript_cuboid/adapter.py tools/featurescript_cuboid/bounded-cuboid.fs tools/featurescript_cuboid/quantities.json cuboid.json --name Cuboid
python -B -m unittest discover -s tools/featurescript_cuboid/tests -v
```

The example supplies length 2 cm, width 0.5 in, and height 0.03 m, yielding
20 x 12.7 x 30 mm. Each dimension requires exactly `value` and `unit`.
Units are `mm`, `cm`, `m`, or `in`; values must be positive finite numbers,
excluding booleans. Converted input dimensions must be in the inclusive range
0.000001 to 1000000 mm. That upper bound applies only during adaptation. Later
package overrides and native edits are not capped by this utility.

Only ASCII space, tab, carriage return and newline may vary between tokens.
Comments, other separators, changed imports, escaped alternative spellings,
expressions, additional code, and other FeatureScript programs are rejected.
Source length is limited to 16384 Python characters. Native names must match
`[A-Za-z_][A-Za-z_0-9]*`. JSON uses Python's normal last-member handling for
duplicate keys; this utility does not promise duplicate-key rejection.

The CLI validates before writing. Rejected input leaves an existing output
unchanged and creates no temporary output. Successful export writes a complete
JSON file using an exclusive sibling `.tmp` file and then replaces the output.
The output directory must exist and that `.tmp` path must be free. I/O failures
can leave the temporary file behind. Errors exit nonzero with Python diagnostics;
very large integers can report `OverflowError`.

## Required package consumer

The published baseline `e7234cd292a5b3a4ff0419f51f4768249ff862d1` supports
the output's `Parameter.unit` metadata. Its `next/src/packages.rs` and
`next/src/bin/packages.rs` are byte-identical to the qualified Source8 and
cached consumer sources. Their SHA-256 values are, respectively,
`d59ce62a012150b845095ec0de8bf65f920df36db5e9bec070fe41accb4c0137` and
`c58fe01c5712bf580ee32e83db660e84669beb9a5172c67fe48b95f33cb3588b`.
This source equality qualifies consumer compatibility; it is not a fresh
compiler build or native runtime test. This utility changes neither consumer
code nor the CAD UI.

The prior qualified consumer was `cad-next-packages` from the evidence's
Source8 package sources, with mm unit metadata support. Its executable SHA-256
is `604c10f24f2e655e85bc03d95fa0a702b126fecf9d80460a6dbb818ba5e8b072`.
Use that tested consumer or a matching installation built from the compatible
baseline. This utility ships no executable or editor/runtime installation.

With a compatible consumer, place the export in a dedicated collection directory:

```sh
cad-next-packages --package-dir collection --id ported.boundedCuboid --parameters '{"name":"AnotherBox","length":20,"width":12.7,"height":30}'
```

The compiler expands the package into ordinary edits: add one `Part::Box`, then
set its `Length`, `Width` and `Height` in mm. It does not mutate a document.
Submit the complete edit array as one public-host transaction using the current
expected revision. Names must be unique in that document. The resulting box
keeps normal native editable properties, Undo/Redo, and save/reopen behavior.
It stores no FeatureScript program or source association.

A compatible editor can select a collection via `--packages collection`.
That option replaces built-ins. To retain them, copy all six matching built-in
package JSON files from that compatible installation into the same collection
alongside the export. Keep the quantities input JSON outside the collection.
Package form length values are numeric mm. No GUI operation was verified here.

## Provenance and verification limits

`adapter.py` is byte-identical to the corrected sealed adapter, SHA-256
`23aca70d95fd52a75e6446035fad3d94b01b996b2dc946142b93e627dc626df8`.
There is no packaging delta to its code or formatting. The correction packet's
seal SHA-256 is
`438186f2a8b7f52dc1c65efd002b45a92c49b11aca91a204e9453c58e68acb57`.
The source, quantities example and canonical package fixture are unchanged
copies from the original authored packet. The fixture is a golden output,
not generated by the test under test.

Prior local evidence packets are named
`cad-featurescript-simple-sol-20261104-r1`,
`cad-featurescript-simple-review-sol-20261104-r1`, and
`cad-featurescript-lexical-fix-20261104-r1`. They are not required to run this
utility or its tests. The independent review qualified two canonical native
controls and six stock FreeCAD saved-box checks. Those prior runs checked
native edits, Undo/Redo, save/Open, box dimensions and geometry. The lexical
correction passed 43 review regressions and 53 separator/control cases, with
canonical output equal to the original. This packaging adds portable adapter
and CLI regressions; it performs no new native or package-compiler runs.

The fixture was authored from the official
[fCuboid APIs](https://cad.onshape.com/FsDoc/library.html#fCuboid-Context-Id-map)
and [feature definitions](https://cad.onshape.com/FsDoc/feature-types.html).
The whitespace restriction follows the documented
[lexical conventions](https://cad.onshape.com/FsDoc/tokens.html).
The declared version/import has not been compiled by Onshape. General
FeatureScript, GUI behavior, extreme-size native modeling and full runtime or
tutorial completion remain unverified. This bounded port grants no full tutorial credit.

## Publication impact

This utility commit is based on published checkpoint
[`e7234cd`](https://github.com/LeoHougaard/CAD/commit/e7234cd292a5b3a4ff0419f51f4768249ff862d1).
The retained publication18 acceptance receipt and its hash-matched raw results
record successful Windows and Linux jobs for both
[ordinary CI](https://github.com/LeoHougaard/CAD/actions/runs/41168325354) and
[native CI](https://github.com/LeoHougaard/CAD/actions/runs/41168325301) on that
exact base. Base acceptance does not establish CI success for this new head.

With only these `tools/featurescript_cuboid/` files changed, the base's existing
`.github/workflows/ci.yml` push and pull-request filters select the full CI
workflow, including `Rust / ubuntu-latest` and `Rust / windows-latest`.
The `next.yml` native migration workflow is not selected by these paths.
The workflows do not run this utility's unittest command. The new head's CI
is pending until GitHub reports its own results; publication can produce
failure notifications. No workflows, ignore rules or
notification settings are changed by this package.
